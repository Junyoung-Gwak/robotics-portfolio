# 승차 허가를 두 번 받으면 어느 단계로 가야 할까

[승강기 연동 현장 사례](../projects/integration.md) · [Python 상태 전이](mission_replay.py) · [시험 코드](../tests/test_mission_replay.py)

**새로 제작한 메시지 재생 실험**입니다. 시설·로봇 연결 없이 요청 식별자와 현재 단계만으로 어떤 이벤트가 상태를 바꿀 수 있는지 확인합니다.

| 순서 | 입력 | 처리 후 단계 | 판단 |
| ---: | --- | --- | --- |
| 1 | 이전 작업의 승차 허가 | 승차 허가 대기 | 작업이 다름 |
| 2 | 현재 작업의 승차 허가 | 탑승 중 | 허가 수락 |
| 3 | 같은 승차 허가 재수신 | 탑승 중 | 현재 단계 유지 |
| 4 | 하차 허가 조기 도착 | 탑승 중 | 현재 단계 유지 |
| 5 | 탑승 완료 | 하차 허가 대기 | 로봇의 완료 수락 |
| 6 | 하차 허가 재수신 | 하차 중 | 허가 수락 |
| 7 | 하차 완료 | 완료 | 로봇의 완료 수락 |

네 종류 이벤트로 만들 수 있는 길이 4의 입력열 256개를 전부 검사하면, 시작 상태에서 완료에 이르는 조합은 승차 허가 → 탑승 완료 → 하차 허가 → 하차 완료 한 가지입니다. 위의 긴 입력에서는 4개 이벤트가 상태를 바꿉니다. 종료 뒤에 같은 요청의 이벤트가 다시 와도 단계가 되돌아가지 않습니다.

이 모형은 조기 도착한 하차 허가를 버립니다. 시설이 허가를 한 번만 보내면 5단계 이후에 계속 기다리게 됩니다. 재시도와 상태 재조회 중 무엇을 지원하는지 양쪽의 통신 계약에서 정해야 합니다. 또한 관제의 허가를 받았다는 기록과 실제 로봇의 승하차를 관찰한 기록은 각각 수집해야 합니다. 이 예제에는 모터 제어, 센서 판정, 통신 재접속, 영속 저장을 포함하지 않았습니다.

```sh
python -m labs.mission_replay
python -m unittest discover -s tests -p test_mission_replay.py -v
```
