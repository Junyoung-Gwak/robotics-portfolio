# 승강기 문이 열린 뒤에도 로봇이 기다릴 때

[포트폴리오 처음으로](../README.md)

시설 관제의 허가는 로봇이 동작을 시작할 수 있다는 이벤트입니다. 실제로 안에 들어갔거나 목적 층에 내렸다는 완료 이벤트는 로봇 쪽에서 확인해야 합니다. 허가를 받았는데도 미션이 이어지지 않는 사례에서 작업 식별자, 현재 단계, 주행 제어권을 시간순으로 대조했습니다.

| 단계 | 확인할 신호 | 판단 |
| --- | --- | --- |
| 승차 대기 | 현재 작업에 대한 승차 허가 | 해당 작업이 승차를 시작할 수 있는가 |
| 탑승 | 로봇의 탑승 완료 이벤트 | 층 이동 단계로 전이할 수 있는가 |
| 하차 대기 | 목적 층 준비와 하차 허가 | 늦게 온 다른 작업의 허가와 구분되는가 |
| 종료 | 하차 완료 및 미션 상태 | 관제와 로봇이 같은 결과를 보고하는가 |

저는 허가 갱신을 현재 요청에 연결하고 잘못된 단계의 허가가 동작을 시작하지 않도록 통신 조건과 회귀 시험을 다뤘습니다. 실제 승하차 운동은 팀의 센서 기반 모듈과 연결했습니다. 현장에서는 한 층간 미션의 승차 허가부터 하차 완료, 이후 과업 성공과 대기 복귀를 확인했습니다.

재접속이 끼는 시나리오에서는 작업 ID와 마지막 완료 단계를 보존하고 양쪽의 종결 상태가 일치하는지 확인해야 합니다. 중복 허가, 이전 작업의 지연 메시지, 목적 층 준비 지연을 하나씩 바꿔보는 것이 다음 시험 설계입니다. 목표·진행 피드백·결과를 구분하는 인터페이스 설계는 ROS 2의 액션 설계 문서로도 살펴볼 수 있습니다. [ROS 2 Actions](https://design.ros2.org/articles/actions.html)
